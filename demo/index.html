Cookie consent for Webflow

One script, one component, every Webflow project.

A small first-party consent script plus a native Webflow component you restyle per client. No account, no per-site plan. Five steps from zero to a compliant banner.

Copy the component Open the live preview
  1. 1

    Host the script once

    Webflow cannot host .js files, so the bundle needs a static URL. Every site points at the same URL; rebuild and push to update them all. Fastest route: push this repo to GitHub and let jsDelivr serve dist/tiny-consent.min.js. 

    https://cdn.jsdelivr.net/gh/<your-user>/tiny-consent@main/dist/tiny-consent.min.js

    Cloudflare Pages, Netlify (drag the dist folder in), or any host you already run works the same.

  2. 2

    Add the head code

    Site settings → Custom code → Head code. Paste this as the first thing, above every analytics or pixel snippet, with no async or defer. Fill in your values and copy.

    Use site-level head code, not page settings, so the script runs on every page. Tags added under Apps & Integrations (the Google Analytics and Facebook Pixel fields) load before custom code and cannot be blocked; paste those snippets into Head code instead.

  3. 3

    Put trackers behind consent

    Categories are essential, analytics, marketing, and personalization. Essential always runs. For each tracker: set type="text/plain", move src to data-tc-src, add the category. 

    <script type="text/plain" data-tc-src="https://www.googletagmanager.com/gtag/js?id=G-XXXX" data-tc-category="analytics"></script>
<script type="text/plain" data-tc-category="analytics">
  window.dataLayer = window.dataLayer || [];
  function gtag(){ dataLayer.push(arguments); }
  gtag('js', new Date());
  gtag('config', 'G-XXXX');
</script>

    Embeds (YouTube, Vimeo, Google Maps) go in a Code Embed element with data-tc-src instead of src. An optional placeholder with the same category disappears once it is allowed. 

    <div data-tc-element="placeholder" data-tc-category="marketing">
  This video loads after you allow marketing cookies.
  <a href="#" data-tc-element="open-preferences">Cookie settings</a>
</div>
<iframe data-tc-src="https://www.youtube-nocookie.com/embed/VIDEO_ID" data-tc-category="marketing" allowfullscreen></iframe>

    Scripts from known tracker hosts (Google Analytics, GTM, Meta, Hotjar, LinkedIn, TikTok, HubSpot, YouTube, Intercom, and more) are blocked even when untagged, including ones injected later by other scripts. A tag that lists two categories (data-tc-category="analytics, marketing") runs only when both are allowed. Remove <noscript> fallbacks from tracker snippets; they fire without consent.

  4. 4

    Paste the component into the Designer

    The button below puts the banner and preferences panel on your clipboard in Webflow's own format: native elements, classes with the default theme, and all data-tc attributes already set. Nothing is an embed, so the Style panel works on every part.

    Preparing the payload…
    1. Open your site in the Designer and select the footer (or any component that is already on every page). Edit the component so the paste lands inside it.
    2. Press Cmd+V (Ctrl+V on Windows). A tc-root div appears with three parts: the banner (bottom-right), the preferences panel, and a small Preferences button (bottom-left) that the script shows once a visitor has made a choice.
    3. Colors and fonts arrive as flat values from the default theme. Select tc-banner, tc-dialog, tc-button, and tc-float and swap them for your site's variables. Then style anything else; names, copy, and layout are free.
    4. Each category row is an accordion. The chevron opens a list of vendors; each vendor opens its cookie table (name, purpose, duration). The vendors in the paste are samples. Replace them with what the site really uses, duplicate a tc-vendor div for each extra one, and give every Privacy policy link its real URL.
    5. Leave the banner visible in the Designer. On the published site the script hides it until it is needed. Hide the preferences panel and the Preferences button while you work and set them back to visible before publishing. Accordion bodies are open in the Designer and start closed on the published site.
    What the attributes do (do not remove these)
    AttributeWherePurpose
    data-tc="root"wrapper divEverything must stay inside it.
    data-tc="banner"banner divShown on first visit.
    data-tc="preferences"panel divCategory panel. Hidden until opened.
    data-tc="float"small button divPersistent "Preferences" button. Shown after a choice, hidden while the banner or panel is open.
    data-tc-action="accept-all"buttonAllow every category.
    data-tc-action="reject-all"buttonDeny every optional category.
    data-tc-action="open-preferences"buttonOpen the panel.
    data-tc-action="save"buttonStore the checkbox selection.
    data-tc-action="close"button, backdropClose the panel.
    data-tc-action="toggle"chevron divOpens and closes the accordion it sits in. Add role="button" and tabindex="0" for keyboard users.
    data-tc-category="…"row div around each checkboxWhich category the checkbox controls. The visible label text is yours to change. The Essential row has no checkbox, only a badge.
    data-tc-element="accordion"row div, vendor divA collapsible box. The script sets data-tc-open on it.
    data-tc-element="details"div inside an accordionHidden while the accordion is closed.
    data-tc-element="chevron"the toggle divRotates 180° while its accordion is open.
    If the paste does nothing

    Webflow reads a specific clipboard format and changes it from time to time. Open the clipboard inspector, copy any element inside the Designer, and paste there to see the exact MIME type and payload shape the Designer currently uses. Compare it with what this page produces (the inspector shows that too). The Copy as HTML embed button is the fallback: paste it into a Code Embed element. It works immediately, but the result is not styleable in the Designer.

  5. 5

    Add a "Cookie settings" link

    Visitors must be able to change their mind from any page. The component's Preferences button already covers that. If you would rather have a plain footer link (or both), add a text link and give it one custom attribute. Element settings → Custom attributes: 

    data-tc-element = open-preferences
  6. 6

    Publish and test

    Publish to the .webflow.io staging domain first and open it in a private window.

    • The banner shows and the Network tab lists no tracker requests.
    • After Accept all, trackers load, a tc_consent cookie exists, and the Preferences button appears bottom-left.
    • Reload: no banner, trackers load straight away, Preferences button still there.
    • Open preferences from that button, expand a row and a vendor, then Reject all: the page reloads with everything blocked.
    • On a phone-sized viewport the banner spans the width and the buttons stack.

Script options, API, events

Script tag attributes

data-tc-modeopt-in (default) or opt-out
data-tc-cookie-daysCookie lifetime, default 180
data-tc-blockExtra hosts, host[:category]. :essential lets a host through.
data-tc-reloadReload when a category is withdrawn (default true)
data-tc-cookie-nameDefault tc_consent

JavaScript

TinyConsent.getConsent()            // { chosen, analytics, marketing, personalization, t }
TinyConsent.isAllowed('analytics')
TinyConsent.setConsent({ analytics: true })
TinyConsent.acceptAll() / rejectAll()
TinyConsent.open() / close() / reset()

document.addEventListener('tc:consent',  e => e.detail)
document.addEventListener('tc:block',    e => e.detail.element)
document.addEventListener('tc:activate', e => e.detail.element)

Honors Global Privacy Control. Consent is a first-party cookie (SameSite=Lax, Secure on https). This kit covers what runs on the site; which categories you need and what your policy says is still your call, not legal advice.
